## Funding Suggestion Review — Accept/Ignore Redesign
- Replaces PAV-214's bulk "Apply suggestions" banner in `ProjectFundingCheckCreate.vue` with a one-at-a-time review flow, sourced from a Claude Design project (`Funding Suggestions.dc.html`, imported via the `claude_design` MCP): each pending suggestion shows score/rank-preview/reasoning with **Accept**/**Ignore** actions and an inline undo bar, instead of merging everything in bulk.
- Accept inserts the suggestion into `orderedMatches` sorted by score, **unselected** (it's just made available, not auto-picked) — this matters because the reset-warning dialog (`hasFundingSelectionChanged`) is keyed off actual selection changes, not the candidate pool changing, so accepting a suggestion alone must never trigger it.
- Ignore is a new BE endpoint `PATCH /projects/:projectId/funding-suggestions/:suggestionId/ignore` (`project.ignoreFundingSuggestion`, same owner/editor/admin gate as `listFundingSuggestions`) that sets `status: "ignored"` immediately, independent of `fundingMatches` — deliberately kept out of the JSON blob per product decision, so it can't be persisted through the existing `afterUpdate` lifecycle hook (which only ever sees entries actually present in submitted `fundingMatches`).
- `project/content-types/project/lifecycles.js` `afterUpdate` filter loosened from `status: "notified"` only to `status: { $in: ["notified", "accepted"] }`, so a suggestion the user accepted-then-later-deselected (or vice versa) keeps tracking the latest submit instead of being locked in after the first one. `"ignored"` deliberately excluded — that status now only comes from the new ignore endpoint and must not be reopened here.
- Fixed a pre-existing bug: `hasFundingSelectionChanged`/`originalSelectedFundingIndices` compared raw array indices, so dragging a card to reorder it (no selection change at all) silently triggered the reset-warning dialog because the same funding's index shifted vs. the saved order. Added identity-based (`external_id`) `originalSelectedFundingKeys`/`currentSelectedFundingKeys` computeds for the actual change-detection; index-based `originalSelectedFundingIndices` is kept only for its original purpose (seeding initial `selectedCards` on load).

## PAV-214 — AI Reverse-Matching: Funding → Project Ideas
- Webhook is project-centric, not funding-centric as the ticket text originally implied: vendor `POST`s to `/api/projects/:projectId/funding-matches` with `{ data: { fundings: [{ id, external_id, title, score, reasoning }] } }` — `external_id` is our own `funding.id` (matches the existing convention in `ProjectFundingCheckCreate.vue`'s `filterFundingsByUserData`), the payload's own `id` is stored only as `vendorMatchId` for debugging.
- BE: new `funding-suggestion` content-type (`project` m2o, `funding` m2o resolved from `external_id`, `external_id`, `vendorMatchId`, `title`, `score`, `reasoning`, `status` enum `new/notified/accepted/ignored`, `notifiedAt`). Idempotency is app-level (find-then-upsert by `project`+`external_id` in the controller), not a DB constraint — matches this codebase's existing convention (no compound unique constraints anywhere else either).
- Deliberately does **not** touch `project.fundingMatches` (the existing AI-proxy-driven candidate/selection JSON blob written by `ProjectFundingCheckCreate.vue`) — the two are separate stores so the webhook can't clobber a user's live in-progress selection.
- Notify decision (`project.js` `receiveFundingMatches`): `score >= threshold OR score > max(score of that project's currently-selected fundingMatches entries)` — the second clause means a below-threshold match still surfaces if it beats what the user already picked. Threshold is `process.env.AI_SUGGESTION_THRESHOLD`, default `0.8` (an admin-configurable `ai-suggestion-setting` content-type was built then dropped per decision — not needed, env var is enough).
- Fan-out reuses the existing `buildEmailHtml`/`emitToUser` lifecycle pattern but is new in one way: recipients are `project.owner` **+ all** `project.editors` together (existing lifecycles only ever notify a single owner or an admin/leader list). New `fundingSuggestion` boolean added to both `components/notifications/app.json` and `email.json`.
